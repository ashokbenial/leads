## 2. What was FIXED in Phase 1 (applied + verified)

All of these are unambiguous defects with safe, local fixes. Each was verified.

### Revenue / metrics correctness (`LF.rev.compute`, dashboard, charts)

1. **NaN poisoning of every revenue aggregate — HIGH.** `pipelineValue`, `weightedForecast`, `closedAmt`, per-source `amt`, and per-owner `wonAmt`/`openAmt` summed `b.amount` unguarded. A single lead with a missing/`null`/non-numeric `amount` turned the whole KPI (hero card, forecast, leaderboard, `fmtCur` → "₹NaN") into `NaN`.
   *Fix:* every sum now uses `Number(x)||0`. Verified: a mixed array `[5000, undefined, null, "7000", NaN]` went from `NaN` → `12000`.

2. **Slipping-deals filter silently dropped the deals it exists to surface — HIGH.** `now - l.updatedAt` is `NaN` when `updatedAt` is missing, and `NaN > x` is `false`, so genuinely stale leads were never flagged.
   *Fix:* falls back to `createdAt`, treats truly date-less leads as not-slipping instead of miscomputing.

3. **Dashboard "Hot Prospects" ignored the user's health formula — MEDIUM.** Hard-coded `l.score>=75` instead of `LF.formula.healthClass(l)`, violating the project's single-source-of-truth convention (a published Customization formula had no effect on this KPI).
   *Fix:* now routes through `LF.formula.healthClass` with the legacy `>=75` as fallback.

4. **"Avg Score Trend" chart labels were one day off and skipped D-1 — MEDIUM.** Labels rendered `D-14 … D-2, Today` (jumping over `D-1`); every point read a day older than its data.
   *Fix:* labels now `D-13 … D-1, Today`, aligned to the data buckets. Verified.

5. **Dashboard offline-fallback sums (`pipelineAmt`, `closedAmt`) had the same unguarded-`amount` bug — MEDIUM.** Guarded.

### Formula engine (`LF.formula`)

6. **Tokenizer silently truncated malformed numbers — HIGH.** A typo'd threshold like `7.5.0` was captured as one token and `parseFloat("7.5.0")` returned `7.5` — the formula "validated", published, and then misclassified every lead against a silently-wrong number.
   *Fix:* the number scanner now throws `Malformed number` on more than one decimal point. Verified: `1.2.3` rejected, `7.5` accepted.

### Runtime crashers (unguarded `.find(...)`)

7. **`LF.runBulkAI` crashed if agent `a2` was ever removed/reset — MEDIUM.** `LF.state.agents.find(a=>a.id==="a2").runs += …` throws `Cannot read properties of undefined`.
   *Fix:* null-guarded.

8. **Bulk-reassign and edit-diff audit strings crashed on a stale owner id — LOW→MEDIUM.** `ownersList().find(o=>o.id===to).name` throws if a lead points at a since-removed team member.
   *Fix:* both sites now fall back to `'someone'`.

9. **Login scan could crash on a team-member row with a null email/username — MEDIUM.** `x.email.toLowerCase()` / `x.credentials.username.toLowerCase()` threw for server-normalized rows with null fields, aborting the entire login.
   *Fix:* both branches null-guarded.

**Verification performed:** `node --check js/app.js` passes, no NUL corruption, server boots and serves all 124 leads via `/api/health` + `/api/snapshot`, and each numeric fix was re-checked with a standalone `node` script.

## 3. DEFERRED — Phase 2: Authentication hardening (needs your decision)

These are real security weaknesses. I did **not** auto-apply them because they change login/credential behavior and, per the old QA notes, some were "demo by design." Recommend doing all of them before any public/untrusted exposure. `leads.ab7solutions.com` is public-facing, so this matters.

1. **Password hashing is non-cryptographic — CRITICAL.** `LF.team._hash` is a 32-bit DJB2 variant with the plaintext **length appended** (`sh1_<hex8>_<len>`). No salt, ~32-bit space, and it leaks password length. Anyone who can read `data/leadforge.json` (the entire DB is one file) can brute-force or collide it offline in seconds; a 32-bit collision authenticates.
   *Plan:* store scrypt/argon2 hashes. The scrypt endpoints described in the stale QA (`/api/auth/hash`, `/api/auth/verify`) and the frontend `_hashAsync`/`_verifyHash` are **not present/not wired** in this build — they need to be implemented in `db-server.js` (Node's built-in `crypto.scryptSync`, no native deps) and actually called by `login`, `setupAdmin`, `confirmAdd`, `saveCredentials`. Add a one-time migration that re-hashes on next successful login.

2. **Sessions are unauthenticated client-side tokens — CRITICAL.** `LF.auth.restore()` rebuilds a full admin session from `LF.state.session` after only checking the row exists and isn't inactive. `expiresAt` is a plain number in the same mutable JSON file; there is no signature/HMAC (the `APP_SECRET` env var is never used). Forging `session:{userId, expiresAt:<future>}` grants a logged-in shell with no password.
   *Plan:* sign the session server-side (HMAC with `APP_SECRET`) and verify on each `/api/*` call; the server, not the browser, must be the auth authority.

3. **`permGate` fails OPEN — HIGH.** `if(!tm) return true;` — any signed-in user whose email doesn't match a `teamMembers` row (email changed, row deleted, snapshot desync, or a forged session) gets **unrestricted access to every module**.
   *Plan:* fail closed for non-admins; only the bootstrap/initial-admin path should be permissive, and it should be explicitly identified rather than inferred from "no row found."

4. **Permissions gate views but not mutations — MEDIUM.** `LF.router.go` checks `permGate(mod,"view")`, but no CRUD handler checks `permGate(mod,"edit")`. A "view"-only user blocked from a route can still reach edit/save paths (e.g. via a drawer opened from an allowed view, or by calling `LF.*` from the console). The `edit`/`admin` ranks in `permGate` are effectively never exercised.
   *Plan:* call `permGate(module,"edit")` at the top of each mutation (`saveLead`, bulk actions, kanban drag-drop, `LF.team.*`), toast + abort on failure.

5. **`mustResetOnFirstLogin` is cosmetic — MEDIUM.** On login it only fires a toast and never clears the flag or forces a change; the "require password change" checkbox in the Team UI does nothing.
   *Plan:* on login with the flag set, force the change-password modal before entering the shell, then clear the flag.

6. **`beforeunload` snapshot flush omits the auth token — LOW.** The `sendBeacon('/api/snapshot')` can't set an `Authorization` header, so once #1/#2 add an API token the final save on tab-close will 401 and be lost silently.
   *Plan:* flush on `visibilitychange` via `fetch(..., {keepalive:true})` with the header instead of `sendBeacon`.

## 4. DEFERRED — Phase 2b: Sync / persistence robustness

7. **Snapshot pull can clobber unsaved local edits (last-write-wins toward server) — HIGH.** On boot and on the 20 s dashboard poll, `LF.db.loadSnapshot()` overwrites `LF.state.leads/…` with server data unconditionally when the server arrays are non-empty. Offline edits held only in localStorage/IndexedDB can be silently overwritten by an older server copy.
   *Plan:* reconcile by `lastWriteAt`/per-record `updatedAt` (accept server only when newer), or skip the pull when a local unsaved-changes flag is set.

8. **"Non-empty guard" prevents reaching an empty state — MEDIUM.** `loadSnapshot` only assigns each array `&& snap.x.length`, so a legitimately empty server (all leads deleted) is ignored and stale local data resurrects and gets pushed back.
   *Plan:* distinguish "server returned empty" from "server returned nothing" (presence of the key), and honor an explicit empty array.

9. **sqlite/IndexedDB round-trip drops fields — MEDIUM.** If the app boots from the `LF.sqlite` path, the fixed 25-column lead schema omits fields like `outcome`, and the kv allow-list omits `formulaExpression`, `pipelineView`, picklists, etc. — they revert to defaults.
   *Plan:* widen the column/kv lists, or (simpler) store leads as a JSON blob column to match the JSON-store shape.

## 5. DEFERRED — Phase 3: Cleanup & consistency (low risk, non-functional)

10. **Duplicate definition: `LF.importLeads`.** Defined at ~3556 (`→ LF.importLeadsReal()`, a full working CSV picker/parser) then re-defined at ~9424 (`→ LF.importer.open()`, the newer wizard). The later wins, so `LF.importLeadsReal` (~40 lines, ~2789) is now unreachable. Confirm the wizard fully replaces it, then delete the orphan to avoid a false sense of a fallback.

11. **Duplicate definition: `LF.runAgent`.** v1 (~2965, simple simulation) is dead; v2 (~5959, real `LF.agentRT` runtime) wins. Delete v1. Also v2 reads `a.name` before guarding `a` (latent crash on unknown id).

12. **`LF.score._stagePts` references a non-existent `"Negotiation"` stage** (`STAGES` has no such entry). Harmless today; remove it or add the stage consistently so `stageProb` doesn't silently weight it `0`.

13. **Loose equality in the formula evaluator** (`==`/`!=`) on a mixed string/number field set (`"" == 0` is true). Consider strict comparison with explicit numeric coercion for numeric fields.

14. **Docs are stale.** `README.md` still describes the old SQLite/`better-sqlite3`/port-8080 setup; reality is the JSON store on port 4000 (per `CLAUDE.md`). `QA-REPORT.md` reviews the retired backend. Update or archive both.

15. **`portal/` is a second, divergent copy of the whole app** (its `index.html` and `js/app.js` differ from root). Decide which is authoritative and remove/merge the other to prevent fixing bugs in the wrong tree.

16. **One self-XSS-only gap:** connected email-account `address` rendered unescaped (~9518). Self-configured data, so low risk; wrap in `escapeHtml` for consistency.

> **Audit did NOT find** (checked and cleared): dead `onclick` handlers (all ~230 `LF.*` references resolve), `data-*`-only dead buttons (sidebar routes are bound in `LF.bindShell`), `grid g-N` column-collapse bugs (only `g-2..g-4` used), or XSS in the main render paths (`escapeHtml` is applied consistently). These common failure modes are cleanly avoided in this codebase.
