AB7 + LeadForge — local setup (Windows / PowerShell)

REQUIREMENT: Node 22 or newer.  Check with:  node -v
  LeadForge WILL NOT BOOT on Node 20 (supabase-js needs the global
  WebSocket added in Node 22). AB7 is more tolerant, but use 22 for both.

.env.local is ALREADY INCLUDED in each folder. Do not delete it.

--- 1. Start LeadForge FIRST (port 4000) ---
  cd leadforge
  npm ci
  npm run dev
  Expect:  Open: http://localhost:4000

--- 2. Then the website (port 3000) ---
  cd ab7solutions
  npm ci
  npm run dev
  Expect:  - Environments: .env.local
           Ready in Xs
  Open a FRESH browser tab at http://localhost:3000

--- IF YOU CHANGE .env.local ---
NEXT_PUBLIC_* values are compiled in when the server BOOTS.
A page refresh will NOT pick them up. You must:
  Get-Process node -ErrorAction SilentlyContinue | Stop-Process -Force
  Remove-Item -Recurse -Force .next
  npm run dev
...then open a NEW tab (not a reload).
NOTE: "rmdir /s /q .next" is cmd.exe syntax and FAILS in PowerShell.

--- TROUBLESHOOTING ---
"supabaseUrl is required" / "NEXT_PUBLIC_SUPABASE_URL is missing"
    -> .env.local missing, OR you didn't do the full restart above.
Homepage shows "Something went wrong"
    -> same cause; do the full restart.
"ws://localhost:3000/_next/hmr failed" in console
    -> symptom of a dead/duplicate dev server, not the cause. Kill node, restart.
"(stale)" badge in the Next.js error overlay
    -> only means a newer Next.js exists on npm. IGNORE IT.
npm install fails on engine check
    -> you are on Node < 22. Install Node 22.

These webhook URLs in ab7solutions/.env.local point at LOCALHOST on purpose:
  LEADFORGE_JOB_WEBHOOK_URL / _VENDOR_ / _PARTNER_
Do NOT point them at https://leads.ab7solutions.com while testing — form
submissions would land in the LIVE CRM.
